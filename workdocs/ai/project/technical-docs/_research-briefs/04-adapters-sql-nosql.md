### for-couchdb (`@decaf-ts/for-couchdb` v0.14.6)

1. **Identity** — dir `/workspaces/decaf-ts/for-couchdb`; package `@decaf-ts/for-couchdb`; version `0.14.6`; description `"decaf-ts couchdb wrappers"` (`package.json:2-4`). ESM-first, dual CJS/ESM export map, `sideEffects: false`; engines Node `>=20`, npm `>=10`; license MPL-2.0.

2. **Purpose & role** — `for-couchdb` is the CouchDB persistence adapter for Decaf.ts. It provides the database-specific glue between the generic persistence abstractions (`Adapter`, `Repository`, `Statement`, `Paginator` from `@decaf-ts/core`) and CouchDB's Mango query / document model: it translates Decaf `Condition`s into Mango selectors, generates CouchDB indexes and design-doc views from model metadata, and normalises CouchDB errors into Decaf `BaseError` types. It is intentionally driver-agnostic (it bundles neither `nano` nor `pouchdb`); concrete subclasses wire in a driver. It sits one layer below the framework core and is itself consumed by `for-nano`, `for-pouch`, and `for-fabric`.

3. **Dependencies** — Runtime/peer decaf modules (all `peerDependencies`, `package.json:101-109`): `@decaf-ts/core`, `@decaf-ts/db-decorators`, `@decaf-ts/decoration`, `@decaf-ts/decorator-validation`, `@decaf-ts/injectable-decorators`, `@decaf-ts/logging`, `@decaf-ts/transactional-decorators`. Dev decaf: `@decaf-ts/cli`, `@decaf-ts/utils`. External runtime deps: **none declared** — `nano`/`pouchdb` are deliberately not in `package.json`; the only CouchDB-client assumption is the duck-typed surface wrapped by `wrapDocumentScope` (`src/utils.ts:61-102`, probing `insert`, `bulk`, `fetch`, `createIndex`, `get`, `put`, `destroy`, `find`, `view`). **Consumers**: `for-nano` (`dependencies`), `for-pouch` (`dependencies`), `for-fabric` (`dependencies`), `for-typeorm` (`devDependencies`), `web-page` (`devDependencies`). The runtime consumer chain is `for-nano`, `for-pouch`, `for-fabric`.

4. **Architecture & structure** — `src/index.ts:3-13` re-exports everything.
   - `adapter.ts` — `CouchDBAdapter<CONF, CONN, C>`: abstract adapter extending core `Adapter`. Implements the CRUD "prefix" hooks that inject CouchDB discriminator fields (`??table`, `_id`, `_rev`) before delegating to abstract `create/read/update/delete/index/raw/view`. Owns `generateId`, `parseError`, metadata helpers, `Statement`/`Paginator` factories, and `initialize()` (calls `index(...)` for all managed models).
   - `repository.ts` — `CouchDBRepository<M, A>`: extends core `Repository`; overrides CRUD to propagate `_rev` metadata and overrides `updatePrefix`/`updateAllPrefix` to run db-decorator handlers, validation, optional merge-with-old, and revision carry-over.
   - `query/` — Mango query subsystem: `Statement.ts` (`CouchDBStatement`, fluent builder, `parseCondition`, aggregate/view pipeline with a manual-aggregation fallback), `Paginator.ts` (bookmark-based paging), `planner.ts` (index planner with scoring + `use_index` attachment and `IndexPlanningError`), `translate.ts` (`translateOperators`), `constants.ts` (`CouchDBQueryLimit`=250, operators), `range.ts` (`nextLexicographicString`/`prefixRange` for `STARTS_WITH`).
   - `indexes/` — `generator.ts` (`generateIndexes`, `generateIndexName`, `generateModelIndexName`): table index, default-query indexes, per-`@index` composite indexes, view-derived indexes.
   - `views/` — design-doc/view subsystem: `generator.ts` (`generateViews`, `generateViewIndexes`, `findViewMetadata`/`collectViewMetadata`), `types.ts` (design-doc/view types).
   - `errors/` — `IndexError` (404), `IndexPlanningError` (carries `suggestion` + offending `query`).
   - `decorators.ts` — view/aggregate decorators `groupBy`, `count`, `sum`, `max`, `min`, `distinct`.
   - `constants.ts` — `reservedAttributes` regex, `CouchDBKeys` (`SEPARATOR:"__"`, `ID:"_id"`, `REV:"_rev"`, `TABLE:"??table"`, `SEQUENCE:"??sequence"`, …).
   - `metadata.ts` — `setMetadata`/`getMetadata`/`removeMetadata` storing `_rev` as a non-enumerable `PersistenceKeys.METADATA` property.
   - `types.ts` — Mango type surface (`MangoQuery`, `MangoSelector`, `MangoResponse`, `CreateIndexRequest`, `CouchDBFlags`).
   - `utils.ts` — `reAuth`, `wrapDocumentScope` (re-authing proxy + `__native` handle), `testReservedAttributes`, `generateIndexDoc`.

6. **Key patterns & concepts** —
   - **Adapter + flavour** (`src/adapter.ts:74-85`): `CouchDBAdapter` extends core `Adapter<CONF,CONN,MangoQuery,C>`; the constructor takes a `flavour` string + optional `alias` used for model registration and `Repository.forModel(Model, adapter.flavour)` lookup. Concrete adapters pass their own flavour.
   - **Method-prefix weaving**: the constructor wraps `create/createAll/update/updateAll` via `prefixMethod` (`@decaf-ts/logging`) to call `*Prefix` hooks first; the prefix hooks inject `??table` and generated `_id`/`_rev` *after* `Object.assign` so model data cannot forge table membership (security guard also enforced by `isReserved`, `adapter.ts:475-482`).
   - **Discriminator multi-table-on-one-DB**: every doc carries `??table = tableName`; doc `_id` is `${tableName}__${pk}` (`generateId`); queries auto-inject `??table`, and `raw()` is force-scoped via `scopeToTable` to prevent cross-table leaks.
   - **Metadata = `_rev`**: revision carried on model instances as non-enumerable `PersistenceKeys.METADATA`; `CouchDBRepository.assignMetadata` propagates it for optimistic concurrency.
   - **Statement/Condition → Mango translation**: Operators → `$eq/$ne/$gt/$gte/$lt/$lte/$not/$in/$regex`; groups → `$and/$or`; `STARTS_WITH` → lexicographic `$gte/$lt` range; `ENDS_WITH` → end-anchored `$regex`; `BETWEEN` → `$gte/$lte`.
   - **Index planner**: introspects `Model.indexes`/`Model.defaultQueryAttributes`, scores candidate indexes (equality×30, range×25, sort×20) and attaches `use_index`; `forceNamedIndexes` (default `true`) gates it; strict mode throws `IndexPlanningError` with a ready-to-paste `@index(...)` suggestion.
   - **Views/aggregates**: `@count/@sum/@min/@max/@distinct/@groupBy/@view` record metadata via `@decaf-ts/decoration`; `generateViews` synthesises design-doc map/reduce JS; aggregates resolve to a real view query or, when a `whereCondition` is present, "manual aggregation" over fetched docs; `avg` is always manual (sum+count of two views).
   - **Error translation** (`adapter.ts:465-577`): HTTP 401/412/409 → `ConflictError`, 404 → `NotFoundError`, 400 → `InternalError`/`IndexError`, `ECONNREFUSED` → `ConnectionError`, plus string heuristics.
   - **Re-auth proxy**: `wrapDocumentScope` re-auths before every operation and exposes the raw connection as `__native`.
   - **Decoration registry**: decorators declared via `Decoration.for(Operator.X).define(...).apply()`; library self-registers with `Metadata.registerLibrary(PACKAGE_NAME, VERSION)` at import.

7. **Lifecycle / configuration / environment** — Importing the module runs `Metadata.registerLibrary(PACKAGE_NAME, VERSION)` (`src/index.ts:52`) using build-time placeholders. `CouchDBAdapter`'s constructor is `protected` (`adapter.ts:79`); consumers must subclass and call `super(scope, flavour, alias?)`. The constructor weaves the CRUD prefix hooks. There is **no flavour decorator or `init()`/`boot()` in this module** — flavour is a plain string passed by the subclass. `adapter.initialize()` (`adapter.ts:116-119`) gathers `Adapter.models(this.flavour)` and calls the abstract `index(...models)` (subclass iterates `generateIndexes(models)` and calls `db.createIndex`). `CouchDBFlags` adds `forceNamedIndexes` (default `true`, `Statement.ts:276-278`), overridable per-statement via `adapter.Statement({ forceNamedIndexes: false })`. Default Mango `limit` = `CouchDBQueryLimit` = `250` (`query/constants.ts:9`); `_id` separator `"__"`. **No env vars** are read by `src/`; all connection/auth config comes through the user-supplied `scope`.

8. **Data & control flow** — *Create*: `repo.create(model)` → core → `adapter.prepare` (segregate transient, map columns, reject reserved) → constructor-woven `createPrefix` sets `??table`/`_id` after `Object.assign` → abstract `create` (`db.insert`) → `assignMetadata` stamps new `_rev` onto result and model. *Read*: `adapter.read` fetches by `generateId(tableName,id)`, assigns `_rev`. *Update*: `CouchDBRepository.updatePrefix` validates PK, optionally reads old model, merges, runs `enforceDBDecorators` + `hasErrors`, carries old `_rev`; `adapter.updatePrefix` re-checks `_rev` exists, injects `??table`/`_id`/`_rev`; subclass `db.insert`. *Query*: `adapter.Statement<M>().from(Model).where(Condition).orderBy(...).limit(n).execute()` → `build()` injects `??table`, parses condition, adds sort, applies default limit (250), attaches default + generated `use_index` → `raw()` force-scopes via `scopeToTable`, calls `adapter.raw` (`db.find`), then either manual aggregation/grouping or `processRecord` (splits `_id` back to pk via `Sequence.parseValue`, `adapter.revert`). *Pagination*: `Statement.paginate(size)` → `CouchDBPaginator`; `page(n)` validates page, looks up cached bookmark (required for non-first pages), strips `skip`, sets `limit=size`+`bookmark`, calls `adapter.raw(...,false)` (full `MangoResponse`), reverts docs, caches next bookmark.

12. **Consumer notes** — You must subclass `CouchDBAdapter` (protected constructor, abstract CRUD/index/raw/view); no ready-to-use adapter ships. Driver is not bundled — bring your own client exposing `insert/bulk/fetch/createIndex/get/put/destroy/find/view` (missing methods are silently skipped, `utils.ts:85`). `forceNamedIndexes` defaults `true`; pass `adapter.Statement({ forceNamedIndexes: false })` to rely on CouchDB's own index selection. Default `limit` is **250** (not CouchDB's 25); set an explicit `limit` or use the paginator for large reads. Pagination is bookmark-based and forward-only (random page access without a cached bookmark throws `PagingError`); `skip` is stripped. Optimistic concurrency: updates require a `_rev` (`updatePrefix` throws `InternalError("No revision number found...")` otherwise). Reserved attributes (`^_.*$`, `??table`, `??sequence`) are rejected. Maturity: pre-1.0 (`0.14.6`); coverage reports stale; `tests/integration/` empty; a stray `console.log` in `views/generator.ts:292`; multiple `TODO`s. Peer deps pinned to `"latest"` (reproducibility-fragile). The exported surface is broad and unmarked `@internal` — treat anything beyond `CouchDBAdapter`/`CouchDBRepository`/`CouchDBStatement`/`CouchDBPaginator`/`generateIndexes`/`MangoQuery` as potentially unstable.

### for-nano (`@decaf-ts/for-nano` v0.13.0)

1. **Identity** — dir `/workspaces/decaf-ts/for-nano`; package `@decaf-ts/for-nano`; version `0.13.0`; description `"decaf-ts persistence adapter for CouchDB via nano"` (`package.json:2-4`). ESM-first, dual ESM/CJS build; engines Node `>=20`, npm `>=10`; license MPL-2.0.

2. **Purpose & role** — `for-nano` plugs the `nano` CouchDB client into the decaf-ts data stack behind the standard `Adapter`/`Repository` abstractions, exposing CRUD, bulk, Mango queries, indexes/views, a change-feed dispatcher, and CouchDB admin helpers. It is a thin, flavour-specific specialization sitting directly on `@decaf-ts/for-couchdb` (`NanoAdapter extends CouchDBAdapter`, `src/adapter.ts:150`), reusing that module's `MangoQuery`, `CouchDBKeys`, `generateIndexes`, `generateViews`, and `wrapDocumentScope`. It is the concrete `"nano"` flavour (`NanoFlavour = "nano"`, `src/constants.ts:7`) registered with the core `Adapter` registry.

3. **Dependencies** — Runtime decaf modules (`dependencies`, `package.json:93-102`, all pinned `latest`): `@decaf-ts/core`, `@decaf-ts/db-decorators`, `@decaf-ts/decoration`, `@decaf-ts/decorator-validation`, `@decaf-ts/for-couchdb`, `@decaf-ts/injectable-decorators`, `@decaf-ts/logging`, `@decaf-ts/transactional-decorators`. Key external: `nano` `^10.1.4`. Dev: `@decaf-ts/cli`, `@decaf-ts/utils`, `@types/jest`. There is **no `peerDependencies` block**; all decaf modules are pinned `"latest"` under `dependencies`. **Consumers** (search across `/workspaces/decaf-ts`): `for-typeorm` (dev), `for-nest` (dev), `for-http` (dev), `for-pouch` (dev), `integrations` (dev), `web-page` (dev), and `bin/releases/dist-nano` (release artifact). It is primarily a leaf adapter pulled in for cross-backend test fixtures.

4. **Architecture & structure** — `src/` is intentionally tiny (6 files) because CouchDB behaviour is inherited from `for-couchdb`:
   - `constants.ts` — `NanoFlavour = "nano"`.
   - `types.ts` — `NanoFlags` (extends `AdapterFlags`, adds `forceNamedIndexes?` and required `user: { name, roles? }`) and `NanoConfig` (`couchUser`, `couchPassword`, `host`, `dbName`, `protocol`).
   - `adapter.ts` — the heart. Exports `NanoAdapter` (extends `CouchDBAdapter<NanoConfig, DocumentScope<any>, Context<NanoFlags>>`) and `createdByOnNanoCreateUpdate`. Subsystems: lazy client lifecycle (`getClient` via `connect`+`wrapDocumentScope`, `shutdown`), `flags()` injecting the authenticated user, `Dispatch()` returning `NanoDispatch`, `repository()` returning `NanoRepository`, `index()` (create Mango indexes throwing `ConflictError` on "existing"; upsert design docs handling 409), CRUD single+bulk, `raw()` (Mango `find`), `view()`, static admin helpers (`connect`, `createDatabase`, `deleteDatabase`, `closeConnection`, `createUser`, `deleteUser`), static `decoration()` wiring `onCreate`/`onCreateUpdate` for `CREATED_BY`/`UPDATED_BY`. Module side effect `Adapter.setCurrent(NanoFlavour)` (`adapter.ts:946`).
   - `NanoRepository.ts` — `NanoRepository<M> extends CouchDBRepository<M, NanoAdapter>`; constructor + `override(flags)` override.
   - `NanoDispatch.ts` — `NanoDispatch extends Dispatch`; subscribes to CouchDB continuous `_changes`, parses frames, groups by `table` (split on `CouchDBKeys.SEPARATOR`) and operation (CREATE rev `1-`/DELETE/UPDATE), calls `updateObservers`; retries up to 3 times with `timeout` (default 5000 ms).
   - `index.ts` — barrel; forces `NanoAdapter.decoration()` on import, re-exports `constants`/`NanoRepository`/`types`/`adapter` (adapter last), build-placeholder constants, `Metadata.registerLibrary`.

   - **Flavour & adapter registry**: `Adapter.setCurrent(NanoFlavour)` registers the flavour on import; `@uses("nano")` binds models to it. Alias flavours resolve to the same handlers via `Operations.get(...)` (tested in `adapter-alias-flavour-resolution.test.ts`).

   - **Repository pattern**: consumers obtain `NanoRepository<M>` via `Repository.forModel(M)` and use CRUD + query builders (`select().where(Condition...).orderBy(...).execute()`).
   - **Dispatch/Observer**: `repo.observe(observer)` subscribes a `NanoDispatch` reading the `_changes` feed; `observer.refresh(table, operation, ids)` fires on mutations.
   - **Revision metadata transparency**: `_rev` captured into `PersistenceKeys.METADATA`, never leaked as a plain field.
   - **Error normalisation**: Nano errors via inherited `parseError`; bulk per-row errors aggregated into one `InternalError`.

1. **Identity** — dir `/workspaces/decaf-ts/for-pouch`; package `@decaf-ts/for-pouch`; version `0.9.5`; description `"decaf-ts persistence adapter for PouchDB"` (`package.json:2-4`). ESM-first, dual CJS/ESM; `sideEffects: false`; engines Node `>=20`, npm `>=10`; license MPL-2.0.

2. **Purpose & role** — `for-pouch` plugs PouchDB (local or remote CouchDB-compatible) into the decaf-ts data stack. 2. **Purpose & role** — `for-typeorm` is the **SQL/relational persistence adapter** in decaf.ts: it implements the abstract `Adapter`/`Repository`/`Statement`/`Paginator`/`Sequence` contracts from `@decaf-ts/core` on top of a TypeORM `DataSource`, providing a uniform Decaf data-access API over relational databases while delegating connection management, entity metadata, and SQL generation to TypeORM. 6. **Key patterns & concepts** —
   - **Flavours**: `TypeORMFlavour = "type-orm"`; `Adapter.setCurrent(TypeORMFlavour)` on import makes type-orm the process-wide default.
   - **Decorator wiring via `Decoration.flavouredAs(...)`**: for each Decaf persistence key (`TABLE`, `ID`, `COLUMN`, `UNIQUE`, `REQUIRED`, `VERSION`, `TIMESTAMP`, the four relation keys, `INDEX`, `CREATED_BY`/`UPDATED_BY`) the adapter registers a flavour-specific implementation that emits both Decaf metadata (`propMetadata`, `relation`) **and** TypeORM metadata (via the local `overrides/`). Run once at import via `decoration()`.
   - **Overrides subsystem**: instead of TypeORM's own `Entity`/`Column`/…, the wiring calls local `overrides/*` which push into `getMetadataArgsStorage()` and use `aggregateOrNewColumn` to merge duplicate column/relation metadata and avoid double-registration.
   - **Context & flags**: `TypeORMContext = Context<TypeORMFlags>`; `TypeORMFlags` extends `AdapterFlags` with `user: string`; `flags()` defaults `user` to `config.username`; `createdByOnTypeORMCreateUpdate` pulls `context.get("user")`.
   - **Repositories/registry**: `Adapter.repository()` returns `TypeORMRepository`; consumers use `Repository.forModel(M)`.
   - **Transaction handling**: `transactionLock()` returns a `TypeORMContextLock`; when active, `getRepository(m, ctx)` resolves the TypeORM repo from `lock.manager()` so all CRUD inside `@transactional()` shares one transaction. `TypeORMContextLock` fully overrides `begin/commit/rollback` without `super` (core's `maxConcurrentTransactions` semaphore is bypassed — documented in README).
   - **Sequences**: `TypeORMSequence` uses Postgres catalog SQL; `pkDec` records `SEQUENCE` metadata so `Model.generatedBySequence`/`sequenceFor` work for bulk id allocation in `createAllPrefix`.
   - **Statement/condition translation**: recursive `parseCondition`; `EQUAL/DIFFERENT` against `null` → `IS [NOT] NULL`; `BETWEEN`, variadic `IN` (`:...param`), `STARTS_WITH`/`ENDS_WITH` (LIKE `%`). `NOT` is **not implemented**.
   - **Error translation**: `parseError` maps Postgres SQLSTATE (`23505`/`23503`/`42P07`→`ConflictError`; `42P01`/`42703`→`NotFoundError`; `42P16`→`IndexError`; `ECONNREFUSED`→`ConnectionError`) + string heuristics.
   - **Observer dispatch**: `TypeORMDispatch` + `TypeORMEventSubscriber` turn TypeORM lifecycle events into Decaf `OperationKeys` notifications.

8. **Data & control flow** — *Create*: `repo.create(model)` → `logCtx` extracts ctx → `createPrefix` (`new this.class(model)`, `enforceDbDecoratorsRecursive` unless `ignoreHandlers`, `hasErrors` unless `ignoreValidation`) → `adapter.prepare` (strip metadata/reserved, drop `undefined`, deep-copy `Date`/nested) → `adapter.create` (`getRepository(m,ctx)`, optional existing-row check → `ConflictError`, else `repo.save`) → `adapter.revert` (rehydrate Model + transient props) → `createSuffix` (CREATE/AFTER handlers). *Read*: `getRepository` → `splitEagerRelations` → `repo.findOneOrFail({ where:{[pk]:id}, relations, loadRelationIds })` → `revert`. *Update*: reads first then `repo.save`. *Delete*: reads then `repo.delete(id)`, returns prior model. *Bulk*: `createAllPrefix` allocates ids via `adapter.Sequence(...).range` when `generatedBySequence`; `adapter.createAll` uses `repo.insert` then `readAll`; `updateAll` loops `update`; `deleteAll` reads then `repo.delete({ [pk]: In(ids) })`. *Query*: `build()` constructs a `SelectQueryBuilder`, applies aggregation/select, `parseCondition` (`qb.where/andWhere/orWhere`), `groupBy`/`orderBy`/`limit`/`skip`; `raw()` checks `ctx.get("allowRawStatements")`, then `getRawOne/getRawMany` for aggregations or `getMany()` otherwise. *Transaction*: `@transactional()` acquires `adapter.transactionLock` → `TypeORMContextLock.begin()` (ensure initialised, create `QueryRunner`, `connect`, `startTransaction`); nested CRUD resolves repos from `lock.manager()`; success → `commitTransaction`+`release`, throw → `rollbackTransaction`+`release`; concurrent `@transactional` calls get independent `QueryRunner`s (Postgres `READ COMMITTED`).

## Summary

Inaccuracies found: **56** total — for-couchdb: 16, for-nano: 10, for-pouch: 16, for-typeorm: 14.

Common cross-cutting themes observed:
- **Stale generated `workdocs/reports`** (RELEASE_NOTES/DEPENDENCIES/CHANGELOG) pinned to much older tags across all four modules.
- **`parseError` 400→`IndexError` branch unreachable** in both `for-couchdb` and `for-pouch` (matches `code.toString()` against a message regex).
- **`*Flags extends RepositoryFlags`** documented in for-nano/for-pouch but the actual base is `AdapterFlags` (no `RepositoryFlags` exists in core).
- **README "Repository" typedef/alias descriptions** for `NanoRepository`/`PouchRepository` are wrong — both are classes extending their CouchDB counterparts.
- **Import side effects vs `sideEffects: false`**: for-pouch (and for-couchdb) declare `sideEffects: false` despite `Adapter.setCurrent(...)`/`decoration()` running at import; bundlers may drop registration.
- **`latest`-pinned decaf deps** across all four modules make installs non-reproducible.
- **Pre-1.0 maturity** everywhere (0.9.5–0.14.6); broad internal APIs exported without `@internal` markers.
- **Dead/stale code**: for-typeorm `decorators.ts` (fully commented), commented `createTable` block; for-couchdb commented `partial_filter_selector` and a stray `console.log`.
- **TypeORM Postgres bias**: sequences, schema helpers, regex, and `parseError` SQLSTATE mapping are Postgres-specific; peer deps declare only `pg`; `nativeRepo()`/`queryBuilder()` reference a non-existent `adapter.dataSource` and are untested.
