### utils (`@decaf-ts/utils` v1.11.1)

1. **Identity** — Directory: `/workspaces/decaf-ts/utils`. Package name `@decaf-ts/utils` (`package.json:2`), version `1.11.1` (`package.json:3`), description `"module management utils for decaf-ts"` (`package.json:5`). ESM-first (`"type": "module"`), dual CJS/ESM export map (`package.json:7-30`), author "Tiago Venceslau and Contributors", MIT. Engines Node `>=20`, npm `>=10` (`package.json:88-91`). Ships two export paths: `"."` and `"./tests"`.

2. **Purpose & role** — Standardizes APIs across the decaf-ts monorepo and provides a reusable foundation for CLI applications and CI/CD scripting. It offers an abstract command framework (`Command<I,R>`), eleven shipped bin entrypoints (build, release, dependency linking, token/credential management, repo mirroring, matrix compilation), interactive prompting/argument parsing, fs/package/http helpers, output-writer abstractions, a performance benchmark harness, and a release-chain orchestration layer. It sits as a leaf utility consumed by virtually every sibling package; its `build-scripts` bundler effectively bootstraps the build pipeline for the whole monorepo. The README positions it as "a light version of the Decaf CLI tool" (`README.md:69`).

3. **Dependencies** — Single decaf-internal dependency: `@decaf-ts/logging` pinned to `"latest"` (`package.json:126`). Notable external deps: `prompts` (+`@types/prompts`) for `UserInput`; `shell-quote` for arg tokenization; `minimist`; `rollup` + `@rollup/plugin-*` for the in-package `build-scripts` bundler; `rimraf`; `jest-html-reporters` for `TestReporter`; `typed-object-accumulator` (`latest`); plus the full build/test/lint/docs toolchain (`jest`, `eslint`, `typescript`, `ts-jest`, `jsdoc`, `prettier`, `nodemon`, `dpdm`, `npm-check-updates`, `clean-publish`). Unusually, everything lives under `dependencies` — there is no `devDependencies`/`peerDependencies` split. Consumers: most decaf packages depend on it (e.g. `cli`, `ts-template`, `with-ai`, `as-infra` all list it; many sibling packages' `build` scripts invoke its `build-scripts` bin).

4. **Architecture & structure** — `src/` is organized by namespace-folder convention (one class per file; types in `types.ts`; constants/enums in `constants.ts`; barrels per folder). The top-level barrel `src/index.ts` aggregates six subpackages via wildcard re-exports — `./cli`, `./input`, `./output`, `./utils`, `./writers`, `./release-chain` (`src/index.ts:1-6`) — plus four build-time placeholder constants `VERSION`/`COMMIT`/`FULL_VERSION`/`PACKAGE_NAME` whose `##...##` tokens are substituted at publish time (`src/index.ts:32-59`).
   - `src/cli/` — `command.ts` (abstract `Command<I,R>`), `constants.ts`, `types.ts`, `commands/` (11 concrete commands + barrel, `src/cli/commands/index.ts:1-11`).
   - `src/input/` — `UserInput` and `ParseArgsOptionsConfig` types.
   - `src/output/common.ts` — `printBanner` + slogan rendering.
   - `src/utils/` — the largest namespace: `constants.ts` (semver, skip-CI flags, `Tokens` enum), `fs.ts` (file/package/dependency ops), `http.ts` (`HttpClient`), `types.ts` (`PromiseExecutor`, `CommandResult`, `DependencyMap`, `Environment`), `utils.ts` (`lockify`, `chainAbortController`, `spawnCommand`, `runCommand`), `performanceRunner.ts` (the benchmark engine), plus `md.ts` and `timeout.ts`.
   - `src/writers/` — `OutputWriter`, `StandardOutputWriter`, `RegexpOutputWriter`, `types.ts`.
   - `src/release-chain/index.ts` — `ReleaseChainRunner`, `runReleaseChain`, `dispatchReleaseChainWorkflow`.
   - `src/bin/` — per-bin entrypoint shims (one `.ts` per `bin` key).
   - `src/tests/` — `TestReporter`, `Consumer`, `jestPerformanceRunner`, `utils` (reachable only via the `"./tests"` subpath export, not the main barrel).
   - `src/assets/slogans.ts` — slogan data for `printBanner`.

5. **Public API surface** — From the main barrel:
   - **CLI framework**: `Command<I,R>` (abstract base; subclasses implement `run(answers)` and optionally `help()`; provides `execute()`, option parsing, help/version/dry-run handling) and `CommandOptions`/`ParseArgsOptionsConfig`. Concrete commands re-exported from `src/cli/commands/index.ts`: `BuildScripts`, `ReleaseScript` (tag-release), `ReleaseChainCommand`, `ModulesCommand`, `NpmLinkCommand`, `NpmTokenCommand`, `RunAllCommand`, `TagReleaseCommand` (shell variant), `CredentialsCommand` (+ `resolveSecret`/`hasSecret`), `CompileMatrixCommand`, `MirrorRepoCommand`.
   - **Input**: `UserInput` (builder methods; static `ask`, `askText`, `askNumber`, `askConfirmation`, `insistForText`, `parseArgs`).
   - **Output**: `printBanner(logger?)`.
   - **Utils** (`src/utils/index.ts:1-6` re-exports `constants`, `fs`, `http`, `types`, `utils`, `performanceRunner`): constants (`Encoding`, `SemVersionRegex`, `SemVersion`, skip-CI flags, `Tokens`, `AbortCode`); fs (`patchFile`, `readFile`, `writeFile`, `getAllFiles`, `copyFile`, `renameFile`, `deletePath`, `getPackage`, `setPackageAttribute`, `getPackageVersion`, `getDependencies`, `installDependencies`, `listFolder`, `listNodeModulesPackages`); `HttpClient.downloadFile`; types (`PromiseExecutor`, `CommandResult`, `Environment`, `DependencyMap`); utils (`lockify`, `chainAbortController`, `spawnCommand`, `runCommand`); `PerformanceRunner` + scenario/phase types.
   - **Writers**: `OutputWriter` (interface), `StandardOutputWriter`, `RegexpOutputWriter`.
   - **Release chain**: `ReleaseChainRunner`, `runReleaseChain`, `dispatchReleaseChainWorkflow`.
   - **Build placeholders**: `VERSION`, `COMMIT`, `FULL_VERSION`, `PACKAGE_NAME`.
   - Secondary entrypoint `@decaf-ts/utils/tests`: `TestReporter`, `Consumer`, `jestPerformanceRunner`, `utils`.

6. **Key patterns & concepts** — The conventions are codified in `workdocs/5-HowToUse.md:508-523` (namespace-by-folder, one class per file, types in `types.ts`, constants/enums in `constants.ts`, always import from the specific file, prefer Singleton/Factory/Observer/Strategy/Builder). `Command<I,R>` is a Template Method (subclasses override `run`; `execute()` orchestrates parsing → help/version short-circuit → prompt for missing answers → `run`). `OutputWriter`/`StandardOutputWriter`/`RegexpOutputWriter` form a Strategy family over process output. `lockify` is a mutex wrapper; `chainAbortController` composes AbortControllers. `ReleaseChainRunner`/`runReleaseChain`/`dispatchReleaseChainWorkflow` implement a workflow-chaining pattern. Credentials resolution in `CredentialsCommand` is a Chain-of-Responsibility (env var → OS keychain → legacy file, `workdocs/5-HowToUse.md:84-88`). The `##...##` placeholder constants are a build-time token-substitution pattern. `PerformanceRunner` is a phased benchmark (warmup/burst/sequential/concurrent modes).

7. **Lifecycle / configuration / environment** — Module lifecycle follows the standard monorepo script flow: `do-install` (npm-token-authenticated install), `on-first-run` boots via `bin/update-scripts.cjs --boot`, `build`/`build:prod` run the in-package rollup bundler then `add:shebang` (injects `#!/usr/bin/env node` + `chmod +x` on `lib/cjs/bin/*.cjs`), `coverage` writes to `./workdocs/reports/data`, releases via `./bin/tag-release.sh` and `clean-publish`. Eleven bin entrypoints (`package.json:35-47`): `modules`, `run-all`, `npm-link`, `npm-token`, `tag-release`, `build-scripts`, `credentials`, `release-chain`, `release-chain-dispatch`, `compile-matrix`, `mirror-repo`. Runtime lifecycle of a `Command`: parse args → resolve `help`/`version`/`dryRun` → short-circuit or prompt via `UserInput` → `run(answers)`. `spawnCommand`/`runCommand` manage child-process output through an `OutputWriter`, resolved/rejected via a `PromiseExecutor`. `"sideEffects": false` enables tree-shaking. Strict TS (`strict`, `noImplicitAny`, `noImplicitOverride`).

8. **Data & control flow** — Three principal channels. (1) CLI arg flow: `process.argv` → `UserInput.parseArgs` (wraps Node `util.parseArgs`) → typed `answers` → `Command.run`; missing required answers trigger interactive `prompts`. (2) Child-process output flow: `spawnCommand`/`runCommand` spawn a process, route stdout/stderr chunks to an `OutputWriter` — `StandardOutputWriter` logs and accumulates, `RegexpOutputWriter` resolves the executor on first regex match; on exit the executor resolves/rejects. (3) Build-time token flow: placeholder constants are substituted by `build-scripts` at bundle time. The release-chain channel routes workflow steps through `dispatchReleaseChainWorkflow` → `runReleaseChain` → `ReleaseChainRunner`.

9. **Testing** — Tests in `tests/`, split into `unit/` (16 files) and `integration/` (5 files), plus a `module-router.ts` helper that selects between `src`/`lib`/`dist` import roots so suites run against source or built artifacts. Jest config uses `ts-jest`, Node env, `--runInBand`, coverage from `src/**` excluding `src/bin`. Coverage reports to `./workdocs/reports/coverage` and `./workdocs/reports/data`. A `trivy` security-scan fixture lives under the tests tree. Several `ReleaseScript`-related suites are `.skip`ped (the tag-release path has reduced automated coverage). The `./tests` subpath export lets downstream packages reuse the `TestReporter`/`Consumer` harness. Circular deps checked via `dpdm` against `./src/index.ts`. Notable gaps: skipped release tests; `md.ts`/`timeout.ts` untested (they are unre-exported).

10. **Usage example** — Custom command (`workdocs/5-HowToUse.md:14-74`): subclass `Command<MyCommandOptions, string>`, pass a `CommandOptions` map to `super('my-command', options)`, override `help()`/`run(answers)`, then `await new MyCommand().execute()`. Credentials (`workdocs/5-HowToUse.md:102-203`): `credentials --action get --name npm` prints the token; `--action setup --rm` enrolls built-in secrets in the OS keychain and removes legacy files; programmatic `resolveSecret('npm')`/`hasSecret('github')` follow env → keychain → legacy-file order. Filesystem (`workdocs/5-HowToUse.md:318-354`): `readFile`, `writeFile`, `patchFile(path, { '{{name}}': 'John' })`, `getAllFiles(dir, filter)`.

11. **Relationships** — Leaf-level utility. Depends only on `@decaf-ts/logging`. Consumed by sibling modules for CLI scaffolding, release automation, credentials, and the shared `./tests` harness. Its `build-scripts` is the canonical monorepo bundler (dual CJS/ESM + type decls + token inlining). `tag-release`, `npm-link`, `npm-token`, `credentials`, `release-chain`, `mirror-repo`, `compile-matrix` are the shared CI/CD primitives invoked by the monorepo's GitHub workflows. `bin/tag-release.sh` is the shell parallel of the TS `ReleaseScript`, kept as a fallback release path.

12. **Consumer notes** — Two entrypoints: main barrel vs `./tests` subpath (separate export map, not reachable from the main import). Build placeholders are literal `"##...##"` in source — only meaningful in a built `build-scripts` bundle. Engine Node `>=20`, npm `>=10`. All deps are runtime (no dev/peer split) — library consumers pull the entire toolchain transitively. `@decaf-ts/logging` and `typed-object-accumulator` use floating `latest` (reproducibility hazard). Credentials resolution prefers env (CI) → keychain (local) → deprecated plaintext files (with warning). Binaries point at `lib/cjs/bin/*.cjs` — build/install before use.

### cli (`@decaf-ts/cli` v0.12.0)

1. **Identity** — Directory: `/workspaces/decaf-ts/cli` (git submodule). Package name `@decaf-ts/cli` (`package.json:2`), version `0.12.0` (`package.json:3`), description `"cli for decaf-ts projects"` (`package.json:4`). ESM, dual CJS/ESM export map. Bin entrypoint `"decaf": "lib/cjs/bin/cli.cjs"` (`package.json:23-25`). Engines Node `>=20`, npm `>=10`.

2. **Purpose & role** — Provides the unified `decaf` CLI entrypoint for the decaf-ts monorepo. It wraps Commander.js with a discovery layer (`CliWrapper`) that crawls the filesystem and `node_modules/@decaf-ts/*` (and sibling packages) for files named `cli-module.[cm]js`, dynamically loads each as a Commander subcommand, and registers a small set of built-in modules (`build`, `release`, `utils`). It sits at the tooling/DevOps layer, relied on by most sibling packages (e.g. `with-ai`, `for-fabric`, `for-nest`, `for-angular`) to drive build/docs/release flows via the `decaf` bin.

3. **Dependencies** — Runtime `dependencies` (`package.json:97-100`): `@decaf-ts/logging` (`latest`) — used pervasively (`LoggedClass`, `Logging`, `LoggedEnvironment`, `toENVFormat`); `commander` (`^13.1.0`) — the CLI engine. `peerDependencies` (`package.json:101-103`): `@decaf-ts/decoration` (`latest`) — used only in `src/version.ts:1` for `Metadata.registerLibrary`. `devDependencies` (`package.json:93-96`): `@decaf-ts/utils` (`latest`) — provides the command classes forwarded by `build`/`release`/`utils` modules and the `build-scripts` bin used by `build`/`docs` scripts; plus `@types/jest`. Consumers: `@decaf-ts/with-ai` depends on it (`with-ai/package.json:112`) and runs `decaf build`; many sibling packages use the `decaf` bin in scripts (`for-fabric/package.json:90-91`, `for-nest/package.json:64-65`, `for-angular/package.json:9,40`).

4. **Architecture & structure** — `src/` layout:
   - `src/CliWrapper.ts` — central class: module discovery, loading, registration, banner/slogan rendering, log-level wiring, `run()` entry.
   - `src/Command.ts` — a custom `Command` subclass of commander's `Command` with an `action()` override (exported but unused internally — see inaccuracies).
   - `src/constants.ts` — `CLI_FILE_NAME = "cli-module"` (`src/constants.ts:11`).
   - `src/environment.ts` — `DecafCliEnvironment` type, `DefaultCliEnvironment`, `DecafCLieEnvironment` accumulated instance.
   - `src/types.ts` — `CliModule` function type.
   - `src/utils.ts` — `CLIUtils` static helper (`loadFromFile`, `normalizeImport`, `initialize`, `packageVersion`, `packageName`, `getPackage`).
   - `src/logging.ts` — `getCmdLogger(cmd)`.
   - `src/slogans.ts` — `readSlogans`, `collectSlogans`, `flattenSlogansWithPriority`.
   - `src/banners.ts` — `banners`, `colorPalettes`, `printAllBanners`.
   - `src/version.ts` — build placeholders + `Metadata.registerLibrary` side-effect (orphaned — see inaccuracies).
   - `src/bin/cli.ts` — the `decaf` bin: `new CliWrapper(process.cwd()).run(process.argv)`.
   - `src/build-module/cli-module.ts` — built-in `build` subcommand forwarding to `@decaf-ts/utils` `BuildScripts`.

5. **Public API surface** — The barrel `src/index.ts:1-3` re-exports exactly three modules:

6. **Key patterns & concepts** — **CliWrapper** extends `LoggedClass`, lazily builds a root commander `Command` (`command` getter), initializing it via `CLIUtils.initialize` which hard-codes `command.name("decaf")`. **Module registration via discovery**: `crawl(basePath, levels)` recursively scans for `${CLI_FILE_NAME}\.[cm]js$`; each hit is `import()`-ed via `CLIUtils.loadFromFile`/`normalizeImport` (handles CJS `default` unwrapping); loaded modules may be a `Function` (invoked) or `Promise` (awaited) and must resolve to a commander `Command`. **Built-in modules**: `INCLUDED_MODULE_FACTORIES = [buildModule, releaseModule, utilsModule]` loaded first. **Discovery scope**: host path → `@decaf-ts/*` scope roots → sibling packages in the enclosing `node_modules`; a `seen` set dedups by resolved path. **commander composition** (not subclassing): `CliWrapper` composes a commander tree and calls `parseAsync`. The custom `Command` subclass is exported but unused internally. **Banners/slogans**: on `run()`, if enabled and not a help invocation, a random ASCII banner is rendered with a random slogan gathered from `workdocs/assets/slogans.json`. No "flavour" concept; the only config knobs are the accumulated `DecafCLieEnvironment` and per-command `--logLevel`.

7. **Lifecycle / configuration / environment** — `run(args)` → `boot()`: `ensureLogLevelSupport` adds `--logLevel` + a `preAction` hook; default `DEFAULT_LOG_LEVEL = LogLevel.info`; loads built-in modules then crawls host/scope/sibling paths. Constructor defaults: `basePath = DecafCLieEnvironment.cliModuleRoot`, `crawlLevels = 4` (the bin passes `process.cwd()`). Environment: `DefaultCliEnvironment = { banner: true, cliModuleRoot, style: true }`; `cliModuleRoot` defaults to `process.cwd()` unless env var `CLI_MODULE_TOOT` (typo) is set (`src/environment.ts:9-12`). Logging pattern defaults to `"{level} [{timestamp}] {app} {context} {separator} {message} {stack}{pId}"` with a custom `pId` parameter. `decaf` subcommands: `build`; `release` (children `chain` alias `run`, `dispatch`); `utils` (children `libraries`, `environment-export`, `print-all-banners`, `modules`, `run-all`, `npm-link`, `npm-token`, `tag-release`, `credentials` with `get`/`store`/`setup`/`git-helper`), plus any discovered modules.

8. **Data & control flow** — `decaf build --dev`: shell resolves the bin → `lib/cjs/bin/cli.cjs` (`src/bin/cli.ts`) → `new CliWrapper(process.cwd()).run(process.argv)`. `run()` awaits `boot()` (log-level support, built-in modules, crawl host → scope → siblings, `import()` each `cli-module.[cm]js`, `addCommand` non-duplicate names). If banner enabled and not help, `printBanner()`. `command.parseAsync(args)` routes to the matched subcommand; for `build`, the `.action` handler builds a value map (`buildValueMap`) then `runUtilsCommand(new BuildScripts(), values, this)` which merges `DefaultCommandValues`, short-circuits on help/version, else calls `BuildScripts.run(payload)`. The `preAction` hook applies any `--logLevel` override.
